# ADR-003: Estandarización de Errores y Excepciones de Coste Cero

## Estado
Aceptado

## Contexto
El volcado de trazas de pila (*stack traces*) completas ante excepciones de negocio previsibles (validación, conflictos, recursos no encontrados) degrada sustancialmente el rendimiento de la JVM en escenarios de alta concurrencia debido al coste nativo de `fillInStackTrace()`. Asimismo, las APIs requieren respuestas de error coherentes y normalizadas.

## Decisión
1. **Excepciones Lean de Coste Cero (`ERR-01`):** `BaseException` y todas las excepciones de negocio derivadas (`ValidationException`, `ConflictException`, `ResourceNotFoundException`, `ForbiddenException`, `UnauthenticatedException`) se instancian con `writableStackTrace = false`.
2. **Catálogo de Errores Tipado (`ErrorCode`):** Cada Bounded Context define sus errores de dominio como un enum tipado (`OrderingError`) implementando la interfaz `ErrorCode` (`ERR-07`), evitando la proliferación de clases de excepción ad-hoc.
3. **Contrato Estándar `ErrorResponse` (`ERR-04`):** Toda respuesta HTTP de error emite un record inmutable con campos `status`, `code`, `detail` y una lista opcional omitida cuando está vacía `errors` (`@JsonInclude(NON_EMPTY)`).
4. **Manejo Centralizado:** `GlobalExceptionHandler` captura todas las excepciones y las traduce al contrato estándar emitiendo logs en nivel `WARN` sin stack trace para excepciones funcionales (`ERR-05`).

## Consecuencias
- **Positivas:** Reducción drástica del overhead de CPU y memoria en la JVM ante flujos alternativos; API estructurada, homogénea y predecible para clientes.
- **Negativas:** La depuración de excepciones funcionales debe guiarse por el mensaje y contexto en lugar de la línea exacta del stack trace.
